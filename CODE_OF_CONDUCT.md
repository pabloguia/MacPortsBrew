# Code of Conduct

MacPortsBrew is a small project about two package managers whose communities
have each given a great deal to the Mac. We want working on it to be pleasant
and productive for everyone, whatever their experience, background or identity,
and whichever package manager they prefer.

This code is written in our own words and is based on the
[Contributor Covenant, version 2.1](https://www.contributor-covenant.org/version/2/1/code_of_conduct/).

## What we expect

- Be respectful and assume good faith. Disagree with ideas, not with people.
- Be patient with newcomers and with questions that have been asked before.
- Give feedback that is specific and kind, and accept it the same way.
- Own your mistakes, apologise to whoever they affected, and learn from them.
- Speak about Homebrew, MacPorts and their maintainers with respect. This
  project treats the two as peers, and so should its discussions.

## What is not acceptable

- Harassment of any kind, in public or in private.
- Insults, personal attacks, or derogatory comments about anyone's identity,
  background or abilities.
- Sexualised language or imagery, and unwelcome attention of any kind.
- Publishing someone's private information without their explicit permission.
- Sustained disruption of discussions, or any other conduct a reasonable person
  would consider inappropriate in a professional setting.

## Where this applies

In every project space — issues, pull requests, discussions, reviews and any
other channel the project uses — and when someone represents the project
elsewhere.

## Reporting

If you experience or witness behaviour that breaks this code, tell the
maintainer privately. Use GitHub's private reporting on this repository
(**Security** tab, **Report a vulnerability**, at
`https://github.com/<owner>/<repo>/security/advisories/new`, where
`<owner>/<repo>` is this repository's GitHub location) and say in the first line
that it is a conduct report rather than a security issue. Reports are read by
the maintainer only and kept confidential.

We aim to acknowledge a report within 7 days. If the report concerns the
maintainer, say so, and it will be handled with that conflict in mind.

## Enforcement

The maintainer decides what action fits, taking the impact on the people
involved into account. In rising order of seriousness, that can be:

1. **A private note** explaining what was wrong, and possibly a request for a
   public apology.
2. **A warning**, with a period of no further interaction with the people
   involved.
3. **A temporary ban** from project spaces.
4. **A permanent ban** from project spaces.

People who report in good faith will not face retaliation for doing so.
